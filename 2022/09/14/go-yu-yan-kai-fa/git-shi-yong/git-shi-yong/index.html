1 架构与参数

固定参数 值 固定参数 值
Git 服务器 公网：124.222.84.111 仓库 admin/learn-dev，私有
Gitea 版本 1.27.3 (迁移时新机必须装同版本) 管理员 admin + 你自己定的强密码
网页端口 3000/TCP 三端统一的远程地址 git@gitea:admin/learn-dev.git(SSH 别名解析)

2 安全策略

2222(Git 推拉)对公网开放：Gitea 内置 SSH 只接受公钥认证，没有输密码的通道，安全等级等同 GitHub。

3000(网页)在轻量防火墙限来源 IP：只允许家宽带公网 IP，服务器不需要开网页。

Gitea 内关闭注册、锁死安装向导、仓库私有；

22 管理端口建议也限家 IP。

更严格的可选做法：2222 也限白名单（三台固定 IP + 家宽 IP）。代价是家宽 IP 变了要改一次防火墙。本手册按”2222 开放、3000 限 IP”写，文末给严格版的差异。

3.6 pitfalls.md 格式

## 2026-09-20 readinessProbe 配错导致 Service 无端点
- 现象：Pod Running，访问 Service 503
- 排查：kubectl describe pod 看探针；kubectl get endpoints 对照
- 根因：探针 path 写错，容器从未 Ready
- 修复：改对 path，Endpoints 自动恢复

4 安装 Gitea

4.1 装依赖、建服务账号和目录

# 安装 Gitea 运行所需的四个依赖：
#   git              — Gitea 底层靠 git 命令做版本控制
#   sqlite           — SQLite3 动态库，Gitea 的数据库引擎（学习场景用 SQLite，免装 MySQL/PG）
#   wget             — 下载 Gitea 二进制文件
#   bash-completion  — 补全 git/gitea 子命令，敲命令少打字
dnf install -y git sqlite wget bash-completion

# 创建一个专用的系统服务账号 git（如果还不存在）：
#   --system           — 系统账号（UID < 1000），不显示在登录界面，安全隔离
#   --shell /bin/bash  — 给它一个能执行命令的 shell（Gitea 内部 SSH 推拉代码时需要）
#   --create-home      — 创建 /home/git 作为家目录（SSH 密钥、known_hosts 存这里）
#   --user-group       — 同时创建同名用户组 git
#   --comment          — 备注，方便以后 who/last 里识别用途
id git || useradd --system --shell /bin/bash --create-home \
  --home-dir /home/git --user-group --comment "Gitea service" git

# 一次性建好 Gitea 运行所需的目录结构：
#   /var/lib/gitea/custom/  — 自定义模板、静态文件
#   /var/lib/gitea/data/    — 数据库存放目录（gitea.db）、仓库本体（gitea-repositories/）、LFS 文件
#   /var/lib/gitea/log/     — 日志文件
#   /var/lib/gitea/tmp/     — 临时文件（dump 备份、上传中转）
#   /etc/gitea/             — 配置文件目录（放 app.ini）
mkdir -p /var/lib/gitea/{custom,data,log,tmp} /etc/gitea

# 把 /var/lib/gitea 整个目录的属主设为 git:git
# 原因：systemd 服务以 git 用户启动 Gitea，它必须有读写自己数据的权限
chown -R git:git /var/lib/gitea

# 设置目录权限为 750（属主 rwx、属组 r-x、其他人无任何权限）
# 原因：防住其他系统用户偷看你的仓库内容和数据库
chmod 750 /var/lib/gitea

4.2 安装二进制

wget -O /usr/local/bin/gitea https://dl.gitea.com/gitea/1.27.3/gitea-1.27.3-linux-amd64
chmod +x /usr/local/bin/gitea
/usr/local/bin/gitea --version        # 必须显示 1.27.3

4.3 生成 4 个密钥

# 生成 Gitea 运行所需的四个安全密钥/令牌：
# 每个 gitea generate secret 都会输出一个高熵随机字符串，存到 shell 变量里
# 供下一步写 app.ini 时自动填入，全程不会出现在命令历史或终端输出中

# 1. SECRET_KEY
#    用途：加密 Cookie、记住登录状态、签名 Session 数据
#    如果泄露：别人可以伪造你的登录 Cookie，相当于绕过密码
SECRET=$(/usr/local/bin/gitea generate secret SECRET_KEY)

# 2. INTERNAL_TOKEN
#    用途：Gitea 内部子进程/组件之间互相调用时的身份验证令牌
#    （如 web 进程调 git 命令、内部 API 互访）
#    如果泄露：攻击者可以调用 Gitea 内部 API 执行特权操作
INTERNAL=$(/usr/local/bin/gitea generate secret INTERNAL_TOKEN)

# 3. JWT_SECRET
#    用途：签发 OAuth2 令牌的 JSON Web Token 密钥
#    （Gitea 的 API Token、OAuth2 应用授权都用它签名）
#    如果泄露：别人可以伪造 API 令牌冒充任意用户调 API
JWT=$(/usr/local/bin/gitea generate secret JWT_SECRET)

# 4. LFS_JWT_SECRET
#    用途：Git LFS（大文件存储）推送/拉取时的认证令牌签名
#    LFS 让你把大文件（图片、二进制等）存到 Gitea 而不塞进 git 历史
#    如果泄露：别人可以读写你的 LFS 文件存储
LFS=$(/usr/local/bin/gitea generate secret LFS_JWT_SECRET)

4.4 写主配置

cat > /etc/gitea/app.ini <<EOF
# ==================== 全局配置 ====================
APP_NAME = Learn-Dev                    # 站点名称，显示在网页标题和左上角
RUN_MODE = prod                        # 生产模式：关闭调试信息、压缩模板、不打印敏感日志
RUN_USER = git                         # Gitea 进程以 git 用户身份运行（和文件权限匹配）
WORK_PATH = /var/lib/gitea              # Gitea 工作目录，custom/data/log/tmp 的父目录

# ==================== 数据库 ====================
[database]
DB_TYPE  = sqlite3                     # 用 SQLite3：单文件、零运维、学习场景足够
PATH     = /var/lib/gitea/data/gitea.db  # 数据库文件路径（账号、仓库元信息、Issue 全在这一个文件里）
LOG_SQL  = false                      # 不在日志里打印每条 SQL，减少日志噪音

# ==================== 仓库存储 ====================
[repository]
ROOT           = /var/lib/gitea/data/gitea-repositories  # 所有 Git 裸仓库的根目录
                                              # 你的仓库实际存在 admin/learn-dev.git/ 下
DEFAULT_BRANCH = main                 # 新仓库默认分支名，和现代 Git 规范一致

# ==================== 服务器/网络 ====================
[server]
PROTOCOL         = http               # 走 HTTP（不配 HTTPS，学习环境够用）
DOMAIN           = 124.222.84.111     # 公网 IP，用于生成克隆地址和网页链接
SSH_DOMAIN       = 124.222.84.111     # Git SSH 克隆地址里的主机名
HTTP_ADDR        = 0.0.0.0            # 监听所有网卡（公网网卡可达），来源限制靠防火墙
HTTP_PORT        = 3000               # 网页访问端口
ROOT_URL         = http://124.222.84.111:3000/  # 网页上所有链接的基础 URL
START_SSH_SERVER = true              # 启用 Gitea 内置 SSH 服务器（推送/拉取代码用）
SSH_PORT         = 2222              # 对外显示的 SSH 端口（客户端连接用这个）
SSH_LISTEN_PORT  = 2222              # 实际监听的 SSH 端口（和 SSH_PORT 一致）
                                     # 2222 和系统管理的 22 端口分开，互不干扰
LFS_START_SERVER = true              # 启用 Git LFS（大文件存储），以后存图片等大文件用
OFFLINE_MODE     = true              # 离线模式：不访问 Gitea 官网下载模板/资源（国内网络稳定）

# ==================== 安全 ====================
[security]
INSTALL_LOCK   = true               # 锁死安装向导：禁止任何人通过网页重新初始化 Gitea
SECRET_KEY     = ${SECRET}           # Cookie/Session 签名密钥（上一步生成的变量自动填入）
INTERNAL_TOKEN = ${INTERNAL}        # 内部组件互相调用的认证令牌（自动填入）

# ==================== OAuth2 / API 令牌 ====================
[oauth2]
ENABLED     = true                   # 启用 OAuth2（API Token 签发依赖此功能）
JWT_SECRET = ${JWT}                 # JWT 签名密钥（自动填入）

# ==================== Git LFS 大文件 ====================
[lfs]
JWT_SECRET = ${LFS}                # LFS 推拉认证令牌的签名密钥（自动填入）

# ==================== 用户/注册策略 ====================
[service]
DISABLE_REGISTRATION  = true       # 禁止任何人自助注册账号（只有管理员能建用户）
REQUIRE_SIGNIN_VIEW   = true        # 未登录用户看不到任何页面内容（仓库列表也不可见）
REGISTER_EMAIL_CONFIRM = false      # 关闭邮件验证（没配邮件服务，开了一半注册不了）

# ==================== 邮件 ====================
[mailer]
ENABLED = false                     # 不启用邮件发送（忘记密码走命令行重置，不走邮件）

# ==================== 日志 ====================
[log]
MODE      = console,file            # 同时输出到终端（systemd journal）和文件
LEVEL     = Info                    # 日志级别：Info（排错时临时改 Debug 看更多细节）
ROOT_PATH = /var/lib/gitea/log      # 日志文件存放目录

# ==================== 其他 ====================
[other]
SHOW_FOOTER_VERSION = false         # 网页底部不显示 Gitea 版本号（减少信息泄露给扫描器）
EOF

chown git:git /etc/gitea/app.ini
chmod 640 /etc/gitea/app.ini

要点：HTTP_ADDR=0.0.0.0 保证公网网卡可访问；

INSTALL_LOCK 锁死安装向导；

DISABLE_REGISTRATION 禁止任何人自助注册。

4.5 注册 systemd 服务

cat > /etc/systemd/system/gitea.service <<'EOF'
[Unit]
Description=Gitea (Git with a cup of tea)

# 网络就绪后启动
After=network.target                          

[Service]

# 主进程常驻型
Type=simple                                   
User=git
Group=git

# 工作目录，也是仓库根
WorkingDirectory=/var/lib/gitea/ 

# 用独立配置启动
ExecStart=/usr/local/bin/gitea web --config /etc/gitea/app.ini  
Restart=always

# 崩溃后 3 秒重启
RestartSec=3s             

# 给 git 用户提供 HOME/GITEA_WORK_DIR
Environment=USER=git HOME=/home/git GITEA_WORK_DIR=/var/lib/gitea  

# 提升文件描述符上限，避免大量仓库时打开失败
LimitNOFILE=524288                          

[Install]
# 多用户运行级（默认开机启动）
WantedBy=multi-user.target                  
EOF

systemctl daemon-reload                       
systemctl enable --now gitea                  
sleep 3                                       
systemctl --no-pager status gitea | head -n 12 

# 如果启用了 SELinux（CentOS 默认 enforce），给 Gitea 目录打默认标签，避免访问被拦截
command -v restorecon >/dev/null && restorecon -R /var/lib/gitea /etc/gitea

/usr/local/bin/gitea admin user change-password \
--config /etc/gitea/app.ini --username admin --password '新密码'

5 防火墙与安全组

5.1 系统防火墙

if systemctl is-active --quiet firewalld; then
  firewall-cmd --permanent --add-port=3000/tcp
  firewall-cmd --permanent --add-port=2222/tcp
  firewall-cmd --reload
  firewall-cmd --list-ports
fi

来源限制交给腾讯云控制台做（轻量的防火墙规则支持源 IP，比 firewalld 管理方便）。

5.2 腾讯云防火墙设置

控制台 → 轻量服务器 → 选中 （124.222.84.111）→ 防火墙 标签 → 添加规则：

应用类型 协议端口 来源 说明
自定义 TCP:2222 0.0.0.0/0 Git 推拉，仅密钥认证，全网可访问（GitHub同款)
自定义 TCP:3000 某宽带公网IP/32 网页，只允许自己访问（百度搜”IP”获取）
SSH TCP:22 某宽带公网IP/32 MobaXterm 管理（建议收紧；出门时临时改）

验收安全策略：

  • 手机关 WiFi 用 4G 浏览器开http://124.222.84.111:3000 → 应打不开/超时（网页被限源）；
  • 但在手机热点网络下，Windows 上ssh -T gitea （第 6 章配完）仍能通 → 说明 Git 通道全网可达、网页不裸奔。

5.3 防暴力扫描

2222 只认密钥、3000 限了 IP，风险已经很低。想更稳可装 fail2ban 看守 22 和 Gitea 网页登录：

dnf install -y epel-release && dnf install -y fail2ban-server
systemctl enable --now fail2ban

6.6 首次推送

PS C:\Users\Administrator> cd e:\learn-dev
PS E:\learn-dev> git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        go/
        k8s/
        ops/

nothing added to commit but untracked files present (use "git add" to track)

`git status` 里确认只有源码/YAML/SQL/笔记，没有`.exe/.db/.key` 等（验证`.gitignore` 生效），然后：


# 把所有未追踪/已修改文件加入暂存区
git add .

# 提交，-m 后跟提交说明（Conventional Commits 格式：chore 表示杂项/构建变更）
git commit -m "chore: 初始化 Go + K8s 学习仓库"

# 把当前分支重命名为 main（Git 默认 init 分支名可能是 master，统一为 main）
git branch -M main

# 添加远程仓库别名 origin，指向 Gitea 上 admin 用户的 learn-dev 仓库
git remote add origin git@gitea:admin/learn-dev.git

# 首次推送到 origin 的 main 分支，-u 设置 upstream 后以后直接 git push 即可
git push -u origin main

如果`git remote add origin` 报`remote origin already exists` （之前已加过），改成
git remote set-url origin git@gitea:admin/learn-dev.git

刷新网页http://124.222.84.111:3000/admin/learn-dev ，看到目录结构即成功。

若提示 remote origin 已存在：git remote set-url origin git@gitea:admin/learn-dev.git 

后续推送：
git add .
git commit -m "你的提交说明"
git push

简洁写法：
git commit -am "你的提交说明"
git push


`-am` 的`-a` 只处理 已追踪文件 的修改/删除， 新文件不会被 add 。`pitfalls.md` 是新的未追踪文件，所以没被纳入。
`.gitignore` 也没改动的话，就出现了`nothing added to commit` 。

先加所有新文件和修改
git add .gitignore pitfalls.md

再提交（此时不需要 -a）
git commit -m "修改.gitignore文件和增加pitfalls.md文件"
git push

一次性操作：
git add .
git commit -m "修改.gitignore文件和增加pitfalls.md文件"
git push`

总结记忆 ：`-am` 适合只有修改没有新文件的场景；有新文件时必须先`git add` 。

8 日常怎么用

8.1 Windows 写 Go

GoLand 写代码 → Ctrl+K（message 示例如go(gin): 练习 JSON 绑定与校验 ）→ Ctrl+Shift+K。网页随时在http://124.222.84.111:3000 查看。

1.看改了啥
  git status

2.提交（有新文件用 add .，只有修改用 commit -am）
  git add .
  git commit -m "你的提交说明"

3.推送
  git push

8.2 服务器写 YAML

cd ~/learn-dev
git pull                                     # 动手前先拉
kubectl apply -f k8s/02-workload/xxx.yaml    # 实验、搞破坏、修复
git add -A
git commit -m "feat(k8s): deployment 滚动更新与回滚实验"
git push

实验结论写进 YAML 顶部五行注释或pitfalls.md 。 推荐 YAML 也尽量在 GoLand 写好推上来 ，服务器只负责 pull 和 apply，减少两端冲突；偶尔在服务器直接 vi 修改也没问题，照上面 commit/push 即可。

8.3 SQL 怎么存

手写练习 SQL（建表、索引、查询、事务演示）：放go/stage2-web-db/sql/ ，正常提交，例如：

# 在服务器或 GoLand 写好后，和普通文件一样提交
git add go/stage2-web-db/sql/01-create-user-table.sql
git commit -m "sql(postgresql): users 表建表与索引练习"
git push

项目的数据库迁移脚本：放各项目自己的migrations/ 目录（如stage5-projects/02-blog/migrations/ ）；

pg_dump 整库导出属于备份不属于代码： 不进 Git ，文件名用*.dump /*.sql.gz 会被自动忽略，需要留存用第 8 章备份机制。

8.4 协作规矩

推送前先拉取 。任何一端 push 报rejected / fetch first ：

git pull --rebase
git push

GoLand 里就是先 Ctrl+T 再 Ctrl+Shift+K。
Go 代码主要在 Windows 改、YAML 主要在 Linux 改、SQL 跟着项目走，天然冲突很少。

9 常用 Git 命令速查

9.1 日常五件套

git status                 # 状态（不确定就先执行它）
git add .                  # 暂存全部（或 git add 路径 精确添加）
git commit -m "msg"        # 提交
git push                   # 推送
git pull                   # 拉取

9.2 看历史与差异

git log --oneline -20
git log --oneline --graph --all
git log --since="1 week ago" --author="admin"
git diff                   # 工作区 vs 暂存区
git diff --staged          # 暂存区 vs 最近提交
git show <commit-id>       # 某次提交的完整改动
git blame main.go          # 每一行是谁、哪次提交改的

9.3 撤销

# 改乱了还没 add：恢复成上次提交
git restore path/to/file

# 已 add 想取消暂存（改动保留）
git restore --staged path/to/file

# 已 commit 没 push：撤销提交、代码保留
git reset --soft HEAD~1

# 已 commit，连代码一起丢弃（确认不要了再用）
git reset --hard HEAD~1

# 已经 push 的错误提交：用反向提交（安全留痕，不要 reset）
git revert <commit-id> && git push

# 提交信息写错且未 push
git commit --amend -m "正确的信息"

9.4 分支

git switch -c exp/statefulset-pv    # 建并切换（旧写法 git checkout -b）
git switch main                     # 切回
git merge --no-ff exp/statefulset-pv
git branch -d exp/statefulset-pv    # 删已合并分支
git push origin exp/statefulset-pv  # 推分支
git push origin --delete exp/statefulset-pv

9.5 暂存现场

git stash                # 收起当前改动
git stash list           # 查看
git stash pop            # 恢复并删除
git stash drop           # 丢弃

9.6 标签

git tag -a stage1-done -m "Go 基础阶段完成"
git push origin stage1-done
git tag

9.7 远程管理

git remote -v
git remote set-url origin <新地址>   # 换服务器时改地址
git fetch --all                      # 只更新信息不合并
git push -u origin main              # 首次绑定上游

9.8 误提交了密钥/大文件

git rm --cached secret.yaml          # 未 commit：移出暂存（配合 .gitignore）
git reset --soft HEAD~1              # 已 commit 未 push：撤回提交
# 已 push：密钥立即作废（换密码/换证书）再处理历史

9.9 GoLand 对应

命令 GoLand 命令 GoLand
add/commit Ctrl+K log/diff 底部 Git 面板
push Ctrl+Shift+K 分支 右下角分支名
pull Ctrl+T stash Git → Uncommitted Changes → Stash Changes
ammend Commit 窗口勾选 Amend

10 备份策略

第一份（实时） ：每次 push 成功，代码同时存在于 Windows 工作副本和 node2 仓库。

第二份（实时） ：master/node1 的 clone 又各有一份完整历史。

第三份（每周全量） ：Gitea 整站 dump（含数据库、所有仓库、账号、密钥），复制到 master 保存。

配置第三份（走 WG 内网传，不占公网流量包）：

# node2 上：生成专用备份密钥
ssh-keygen -t ed25519 -N '' -f ~/.ssh/id_ed25519_gitbackup
cat ~/.ssh/id_ed25519_gitbackup.pub
# 把输出追加到 master 的 /root/.ssh/authorized_keys
# master 上执行：mkdir -p /root/gitea-backup

# node2 验证免密
ssh -i ~/.ssh/id_ed25519_gitbackup root@10.8.0.14 hostname

node2 上crontab -e 加一行（每周日 03:00，自动清理 30 天前的旧包）：

0 3 * * 0 mkdir -p /var/backups/gitea && sudo -u git HOME=/home/git GITEA_WORK_DIR=/var/lib/gitea /usr/local/bin/gitea dump --config /etc/gitea/app.ini --file /var/backups/gitea/gitea-dump-$(date +\%F).zip && find /var/backups/gitea -name 'gitea-dump-*.zip' -mtime +30 -delete && scp -i /root/.ssh/id_ed25519_gitbackup /var/backups/gitea/gitea-dump-$(date +\%F).zip root@10.8.0.14:/root/gitea-backup/

先手动跑一次验证：

sudo -u git HOME=/home/git GITEA_WORK_DIR=/var/lib/gitea \
/usr/local/bin/gitea dump --config /etc/gitea/app.ini --file /var/backups/gitea/test.zip
ls -lh /var/backups/gitea/

10 迁移到新服务器

公网方案下迁移 = 新机装同版本 Gitea + 恢复数据 + 三端把 IP 改成新公网 IP。

10.1 旧 node2 打包

先确认三端代码都已 push

systemctl stop gitea
/usr/local/bin/gitea --version | tee /root/gitea-version.txt   # 确认 1.27.3
tar czpf /root/gitea-migrate.tar.gz -C / \
  etc/gitea var/lib/gitea usr/local/bin/gitea root/gitea-version.txt
systemctl start gitea        # 切换验证期间旧机保持可用

10.2 新机装同版本外壳

1.新机轻量防火墙先按 3.2 配好（2222 开放、3000/22 限你家 IP）；

2.在新机执行 第 2 章 2.1～2.5 （建用户、装 1.27.3、写配置时 DOMAIN 先写新机公网 IP、建 systemd 服务），不用建管理员。

10.3 传数据并恢复

在新机器执行。

scp root@124.222.84.111:/root/gitea-migrate.tar.gz /root/
systemctl stop gitea
tar xzpf /root/gitea-migrate.tar.gz -C /
chown -R git:git /var/lib/gitea
chown root:git /etc/gitea/app.ini && chmod 640 /etc/gitea/app.ini
# 把配置中的旧 IP 换成新机公网 IP（假设新机 IP 为 NEW_IP）
sed -i \
  -e 's|^DOMAIN *=.*|DOMAIN = NEW_IP|' \
  -e 's|^SSH_DOMAIN *=.*|SSH_DOMAIN = NEW_IP|' \
  -e 's|^ROOT_URL *=.*|ROOT_URL = http://NEW_IP:3000/|' \
  /etc/gitea/app.ini
command -v restorecon >/dev/null && restorecon -R /var/lib/gitea /etc/gitea /usr/local/bin/gitea
systemctl daemon-reload && systemctl enable --now gitea
systemctl --no-pager status gitea | head

10.4 三端切换

各改一处，因为都用 gitea 别名

  • Windows ：改C:\Users\你\.ssh\config 里HostName 为新 IP；
  • master / node1 ：
sed -i 's/^    HostName .*/    HostName 新IP/' ~/.ssh/config

仓库的 remote 写的是别名git@gitea:... ， 不需要改 remote 。

10.5 验证与收尾

  1. 网页http://新IP:3000 登录，确认仓库、历史、SSH 密钥、账号都在；
  2. GoLand Ctrl+T 拉取、改文件 Ctrl+Shift+K；
  3. mastergit pull 验证；
  4. 在新机重建第 8 章的备份密钥和 crontab；
  5. 旧机到期释放。
